## Implemented under sentinel-console/ (isolated branch, not production execution)

### 1. Trade Memory
- `POST /api/brain?action=syncTrades`: fetch *complete* broker closed trades from the authenticated MT5 Demo account, up to the current provider-returned window (up to 5,000 rows/request).
- Idempotent `sentinel_brain_trades` records, keyed by account+ticket+close-time. Records are not lost when the browser closes.
- Real account-level trade count, broker-reported P/L and unknown attribution count. Provider commission/swap may be incomplete; not labeled as audited net performance.

### 2. Broker Historical Lab
- `POST ...syncCandles`: broker-native symbol and M5/M15/H1/H4/D1; stores up to 10,000 valid bars per call in `sentinel_brain_candles`.
- Retains `coverage`, `truncated`, `stopReason`, raw and missing spread quality, avoiding silent zero imputation.
- Fixed-rule tests for EMA pullback, Donchian breakout, RSI mean reversion, volatility expansion.
- Signals use only candles closed before the next-bar entry. Stop-loss takes priority where both stop and target touch in the same bar; gap stop uses adverse open.
- 3 non-overlapping chronological out-of-sample windows, no train-on-future and no automatic parameter optimization.
- 2x transaction friction stress; insufficient, partial or unknown-spread data blocked from promotion.

### 3. Strategy Selector
- `PAPER_CANDIDATE`, `PAUSE_RESEARCH`, `INSUFFICIENT`, `COST_DATA_WEAK`, `DATA_INCOMPLETE`.
- `sentinel_brain_order_tags`: can record the originating strategy only for a **currently open MT5 Demo position within 120 seconds of its recorded opening time**, with an immutable ticket/strategy/risk record.
- Closed broker trades join this immutable pre-close ledger, enabling fair forward strategy evaluation. Without this ledger, closed trades are `UNATTRIBUTED` and are **not** guessed into strategy buckets.
- After sufficient **tagged** forward trades, persistent negative performance leads to research priority 0x; robust positive forward evidence leads to a **2x relative paper-research sampling priority**, normalized within a fixed experiment budget. It does **not** increase lot size, capital risk, or send broker orders.

### 4. Dashboard
- Replaced disconnected "AI Lab" screen with live-data "العقل المتعلّم": account trade memory, imported candle counts, provider-native symbol choices, history windows, OOS evidence, priority decisions.
- Click-driven import + evaluation workflow. Current browser action starts the job. The feature is **not a permanently running learning service yet**.

## Next engineering priorities

1. **Deploy once after quota reset** and confirm all SSO-protected `/api/brain` endpoints respond correctly.
2. Import initial broker history by symbol and timeframe, check missing historical range / spread, build baseline paper-only reports.
3. Obtain the *actual current Grok bot repository/export* before wiring execution, trading risk, or strategy changes; legacy repo may not be its source.
4. Build a continuously running Demo-only strategy worker using TickerAll WebSocket ticks/position/account events, durable order queue, idempotency keys, broker reconciliation on restart, managed stop-loss/take-profit and duplicate-order protection.
5. Persist fill/strategy/risk attribution immediately upon open and update selector after every completed trade. Risk per trade requires broker-native contract info, not approximate default pip tables.
6. Add regime-specific lookback and champions/challengers after sufficient real data, purged cross-validation and trial registry, feature availability checks, model drift detection, rollback, and out-of-sample stress tests.
7. Only then consider automatic **paper** risk sizing using a shared portfolio risk budget. Do not equate 2x performance weight with unbounded leverage.

**General principle:** A profitable-looking synthetic backtest is never proof of profitable broker execution; self-improvement is evidence-aware, reversible, and measurable, not unbounded automatic parameter adjustment.
