## Worker implementation
- `worker/runner.js` — deployed event worker with a Neon SQL lease preventing overlapping cycles; no orders endpoint exists.
- `worker/neon-function.mjs` — trigger-only fetch handler; rejects public requests missing verified `x-neon-trigger-invocation-id` and a matching schedule name; no access keys in frontend.
- `brain/strategy-factory.js` — 16 deterministic seed combinations, mutation/offspring, source-quality screening, chronological validation and held-out segment, pessimistic execution costs, independent UTC daily blocks, research-only ranking/retirement.
- `brain/public-feed.js` — hourly BTCUSDT spot candles from Binance's **public** market-data-only URL. Saved in distinct `sentinel_autonomy_public_* ` tables. No broker spread is supplied; optional assumed costs are for hypothesis ranking, NEVER broker promotion.
- `brain/research-radar.js` — Crossref publications metadata twice daily. Titles/DOIs are discovered, not fully read or scientifically confirmed.
- `api/autonomy.js` — read-only status of worker heartbeat, cycles, candidates, sources, with Vercel SSO.
- `brain-ui.js` — live state, leaderboards and citations in Intelligence after the Vercel build is deployed.

## Actual cadence
- A Neon Function Trigger POST invokes every 15 minutes around the clock (with normal provider/service availability limits).
- When an MT5 demo session is HOT, attempt new real candle imports at most every two hours for broker-listed XAUUSD/GOLD, BTCUSD, EURUSD and NAS100/US100/USTEC, on M15 and H1.
- When the broker is cold or unavailable, replay **only previously imported broker candles**; never make synthetic candles. On weekends, no fresh FX/gold bars are assumed.
- Try the no-key Binance public BTCUSDT hourly feed every two hours, completely separated from MT5 broker candles and MT5 bonus decisions. Binance geographic restrictions and rate limits may block the feed; failures are persisted.
- Bibliographic Crossref queries at UTC hours 04 and 16, metadata-only, with provider attribution.
- Reward once per genuinely changed dataset and 7+ days, as PAPER RESEARCH POINTS, **not lot or position-size increases**. On repeated same market data no repeated reward.

```sql
SELECT status,last_heartbeat_at,last_success_at FROM sentinel_autonomy_worker_state WHERE worker_name='sentinel-autonomy';
SELECT started_at,status,totals,notes FROM sentinel_autonomy_cycles ORDER BY started_at DESC LIMIT 5;
SELECT symbol,timeframe,status,reward_points,metrics->'holdout' AS holdout
  FROM sentinel_autonomy_candidates ORDER BY last_evaluated_at DESC LIMIT 20;
SELECT provider,symbol,timeframe,candle_count FROM sentinel_autonomy_public_hypotheses ORDER BY created_at DESC LIMIT 5;
```

The recent GitHub Actions run is the source of truth for syntax/tests; it does not prove remote provider can reach all external URLs. Never send live trade commands based on these outputs without a separate **DEMO-only broker validation and execution project**.
